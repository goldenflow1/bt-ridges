## Round 3 (third pass, `docs/reviews/2026-09-29-third-pass.md`)

All three findings plus the dirty-workspace caveat reproduced in `tests/scenario/test_review_2026_09_29_round3.py` (6 of 6 failing before the fix), then fixed.

| Finding | Fix | Requirement |
|---|---|---|
| F2 runtime files outside source extensions | Fingerprint = diff + every untracked file except a denylist of disposable artifacts (`__pycache__`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.tox`, `node_modules`, `htmlcov`, `*.log`, `*.pyc`, `.coverage*`, `coverage.xml`, `junit*.xml`, …). Unknown formats count by default. | H-SHELL-08 |
| F4 hand-off exception | `safe_handoff()`: retry once; if cleanup still fails, return the patch only if `git apply --check` passes on the tree as it is, else nothing | H-SHELL-07 |
| F6 credential dedup | Same connection identity ⇒ merge; known password/test DB replace unresolved ones | H-PROF-05 |
| Dirty-workspace caveat | `undo_run_changes()` no longer resets the whole index; only run-changed paths are restored. The spec now states this is a local-use safety property, not a general start-state guarantee | H-GIT-05 |

Accepted trade-off: the artifact denylist means a check that writes, say, a `.log` file the patched code later reads would still be missed. That is judged far less likely than test runners dropping caches/reports into the tree, which would otherwise make every such candidate "unstable".
