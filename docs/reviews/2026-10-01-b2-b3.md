# B2/B3 finalization review

Reviewed implementation: `580a459`, with plan status recorded in `635410f`. The working-tree corrections below apply to that implementation; they do not promote a new submission.

## Findings corrected

| Priority | Finding | Correction and regression evidence |
|---|---|---|
| P1 | Finalization reused a tool-timeout callback closed over the expired driver timer. Recovery shell commands were limited to five seconds even when 225 seconds remained. | Rebind the callback to the finalization timer; cap tool time by actual remaining phase time. A fake-clock workflow verifies recovery receives its own allowance. |
| P1 | After a long baseline, the driver timer could consume all remaining working time. The separate finalization round then had no time allocation. Requiring all 60 seconds still to remain also made small guard overhead prevent recovery. | Reserve 60 seconds outside the driver slice, preserving the existing separate hand-off reserve. Permit recovery with the remaining window when enough time for a model attempt remains. The regression includes a 525-second baseline and guard overhead. |
| P1 | An empty guarded diff still ran statement checks against unchanged code before recovery. Those checks could consume the time intended for the first useful edit. | Skip redundant post-driver checks for an empty diff; return unknown check evidence, not a passing result. |
| P2 | Two `finish` calls in one model reply bypassed the one-time refusal before the model had any chance to respond to it. | Decide whether to refuse after processing the complete tool batch. A later reply may still honestly finish without a patch. A finish followed by a valid edit in the same batch is accepted. |
| P2 | Refusing a finish cleared `finished` but retained its summary and target symbol. The stale symbol could later influence the patch guard. | Clear all finish metadata when the empty finish is refused. |
| P2 | Empty-finish recovery checked time but not whether another model request was affordable. | Quote the next request, including tool schemas, output allowance, refusal text and the model selected by cooldown state, before requesting another turn. |

The first five findings were reproduced by five failing tests against the original implementation. The affordability check also has a regression test with positive remaining money that is insufficient for another request.
