# A0 and A1a implementation review

Reviewed implementation: commit `9f88963`. Scope: the HTTP deadline transport, retry/routing state, budget-refusal classification, and their tests. Corrections are in the working tree; this review does not promote v004.

## Findings and corrections

| Priority | Defect reproduced before correction | Correction |
|---|---|---|
| P1 | The watchdog could not interrupt connection setup while `connection.sock` was absent. A simulated 0.35 s connection returned after 0.35 s despite a 0.08 s timeout, and issued the request after expiry. | Bound the caller's wait with a daemon exchange worker; recheck cancellation after connect and before sending. Late connections close without issuing the request. |
| P1 | With HTTP/1.0/`Connection: close`, `getresponse()` detaches the socket from the connection. A delayed header followed by a stalled body took about 0.50 s with a 0.30 s timeout. | Retain the original socket for deadline updates and cancellation throughout body reading; close the response as well as the connection. |
| P1 | `read1()` EOF could accept a body shorter than `Content-Length`, even when the bytes happened to form valid JSON. | Reject incomplete bodies and retain possibly billed reservations through the existing transport-error accounting path. |
| P1 | Any `Retry-After` header made an explicit `budget_exhausted` response temporary, including malformed headers. | Explicit hard exhaustion wins. Only an explicit temporary code or an otherwise unclassified 402 with valid retry advice can be retried. |
| P1 | Error classification scanned the complete body for generic words such as `budget`, so invalid request parameters and echoed request data could permanently mark the wallet spent. | Read error code/type/reason/message fields and require an explicit exhaustion/cap-exceeded marker. |
| P1 | Symbolic error codes in an HTTP-200 error envelope were passed to `int()`. Two temporary reservation errors became 502 failures and switched the model. | Preserve symbolic budget classification, including hard-cap termination, before retry/routing decisions. |
| P2 | Positive infinity was accepted as a retry delay; the final failed attempt still slept, even though no further attempt would be made. | Reject nonfinite delays; omit the final sleep; stop rather than wait unboundedly when no call deadline is supplied. |
| P2 | Calls starting on fallback during cooldown and the later primary recovery probe had no transition reason in telemetry. | Record both decisions on their attempt records, including successful attempts. |
| P2 | A fallback identical to the primary could create meaningless cooldown state; the implementation retried only selected 5xx statuses despite the spec's 5xx requirement. | Avoid self-switches and apply the existing bounded retry policy to the full 5xx range. |

The first regression run against the uncorrected implementation reproduced 17 failing cases, including parameterized variants. The original tests passed the HTTP paths after allowing localhost sockets; the new cases exposed gaps in their coverage.

## Remaining boundaries

- Portable socket timeouts cannot cancel a system DNS resolver. The caller returns at the deadline; a daemon worker can remain until connect returns, then closes without sending. Timed-out requests that may have reached the provider retain their unknown-cost reservation.
- This completes review of **A0's inference transport**. It is not evidence that every tool, Git operation, and cleanup path in the broader A0 plan has a shared end-to-end deadline. Finalization and candidate hand-off remain part of the pending B2/B3 work.
- The corrected bundle needs the planned compatible dev/public no-regression check and frozen-release G7. Earlier diagnostics on `f378c926` do not measure the corrected build. No paid inference or upload was performed in this review.
- The persistent-fallback defect is reproducible. That establishes a mechanism consistent with the production billing evidence, not the exact per-request error sequence in production.

The duplicate experiment ID for this work has been corrected to E012; E011 remains the historical v003 reliability experiment.
