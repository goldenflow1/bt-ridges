### G1 (P3) go-sqlx-pagination: backfill behind the cursor during a walk must not cause repeats

```go
func TestHiddenBackfillDuringWalkNeverRepeats(t *testing.T) {
	s, _ := openTestStore(t)
	var live []int64
	for i := 0; i < 6; i++ {
		live = append(live, record(t, s, "tern", "live", "doc.view", base.Add(time.Duration(10+i)*time.Minute)).ID)
	}
	page, err := s.ListEvents(context.Background(), "tern", "", 2)
	if err != nil {
		t.Fatal(err)
	}
	seen := []int64{page.Events[0].ID, page.Events[1].ID}
	for i := 0; i < 3; i++ { // older than the cursor, written mid-walk
		record(t, s, "tern", "backfill", "doc.view", base.Add(time.Duration(i)*time.Second))
	}
	for cursor := page.NextCursor; cursor != ""; cursor = page.NextCursor {
		if page, err = s.ListEvents(context.Background(), "tern", cursor, 2); err != nil {
			t.Fatal(err)
		}
		for _, e := range page.Events {
			seen = append(seen, e.ID)
		}
	}
	if !equalIDs(seen, live) {
		t.Fatalf("got %v want %v", seen, live)
	}
}
```

Keyset paging serves `live` exactly once. An offset-based variant re-serves live ids 1 and 2.

   `l.254-271`, CH `l.252-260`, Go `l.202`, Django `l.173-182`) are enforced on production code and should grow with
   new fixture literals.
2. **The region filter is non-discriminating in the fanout hidden tests.** `test_mixed_customers_rank_by_true_revenue`
   passes `region="east"` and `test_customers_without_qualifying_orders_report_integer_zero` passes `region="west"`, but
   every customer in each test belongs to that region. F9 relies entirely on the visible `test_region_filter`. That is
   acceptable because the visible test is required, but the hidden names suggest more than they check.
3. **Go `split-predicate` is declared `passes_visible: false`.** I confirmed it fails the visible
   `TestListEventsOrdersByTimeNotID` (`store_test.go:139-148`): after `early` (id 2), `created_at >= base AND id > 2`
   excludes `late` (id 1), so the walk returns `[2]`. The G3 behaviour therefore has no decoy that passes the visible
   tests. Suggested extra decoy `or-predicate.patch`: `AND (created_at > $2 OR id > $3)` with `ORDER BY created_at, id`.
   - It passes all visible tests. Ids are monotonic in time in `WalksAllPages`, and in `OrdersByTimeNotID` the walk
     is `[2, 1]`.
   - It fails only `TestHiddenBackfilledEventsHaveIDsOutOfTimeOrder`: after live id 1 (10 min), `id > 1` readmits
     backfill ids 7-15, so 7 is served again.
4. **CH `final-with-prewhere` depends on the pinned server version.** It is a valid decoy only because in 24.8 an
   explicit `PREWHERE` is evaluated before `FINAL` dedup. Newer ClickHouse releases add a setting to apply PREWHERE
   after FINAL; if it becomes the default, this decoy turns into a correct fix and B-VALID-03 would fail. Keep
   `tests/clickhouse.Dockerfile:1` pinned, or note the dependency in the decoy JSON. (The 2026-09-29 bench-catalog
   review, l.75, records that all supplied decoys currently fail hidden groups.)
5. **Decoy `expect_failing` lists are subsets, not exact** (`bench/validate_task.py:57`), and several understate:
   - `final-with-prewhere` also fails `test_revision_not_timestamp...` (account 43) and
     `test_tenant_with_only_inactive...` (ember).
   - `annotate-without-distinct` also fails `test_rating_rounding...` and `test_filtered...`.

   This is harmless, but the JSON undersells what each decoy demonstrates.
6. **Python aggregation over prefetched rows (Django) is not forbidden by the checker.** A fix that does
   `prefetch_related("tags", "ingredients", "reviews")` and computes `len(...)` plus a Python mean fed to
   `rating_payload` would issue 5 queries and produce identical JSON, including the 4.125 case. It passes every test.
   The statement's "Keep the work in the ORM and PostgreSQL" arguably forbids it, but the "Python-side re-querying per
   recipe" wording and `construct_limits` do not. Decide whether this is acceptable; if not, the statement should say
   "compute counts and averages in PostgreSQL".
7. **The Django test name `test_rating_rounding_matches_model_and_detail` asserts more than its name says.** It also
