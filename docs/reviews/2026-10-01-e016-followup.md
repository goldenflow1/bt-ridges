## Remaining blockers

### P1 — Declared stop conditions do not stop dispatch

`tools/run_bench.py:435–480` records reconciliation failures and input changes but continues scheduling. An infrastructure-blocked slot only prints a message. There is no experiment-level counter for the protocol's two blocked slots or three consecutive incomplete trials.

An offline probe used `tests.unit.test_fault_proxy.stub_bench` and replaced `reconcile_proxy` with a response reporting `key usage differs from proxy real cost` on every trial. **All eight trials were dispatched**, despite the first trial meeting the protocol's immediate-stop condition.

The only spending limit in the runner is the shared `--ceiling` (default $30). The protocol does not yet supply an executable configuration or wrapper enforcing the pilot's additional $0.50 limit, main cohort's $4 limit, and retained $5 of key headroom. These need pre-dispatch reservation checks; stopping only after the limit is exceeded does not establish an under-$0.50 pilot.

Required verification: a mismatch or mutated input stops before the next dispatch, including setup replacements; blocked/incomplete counters stop at their declared thresholds; an allowance that would exceed the pilot/main envelope or retained headroom cannot be dispatched. An explicitly tested launcher can enforce the experiment limits; new runner flags are not the only possible solution.

### P1 — Recording a result releases its reservation without reconciliation

`SessionLedger.record()` (`tools/run_bench.py:232`) always removes `pending`. Its caller at line 446 passes the raw key-usage delta, even when proxy reconciliation failed or billing remains uncertain. Two unchanged usage reads are not proof that a delayed charge cannot arrive.

Offline reproduction with a $1 ceiling and a usage reader returning zero:

1. Reserve $0.60 for an unfinished/uncertain trial.
2. `fits(0.50)` is false.
3. Record that trial with a zero usage delta and no known consumed cost, as the runner can currently do after incomplete accounting.
4. `fits(0.50)` becomes true: the outstanding allowance disappeared.

When the usage delta is unavailable, the caller also passes `cost_accounted` as the fallback ledger figure. In a multiplier run this is synthetic agent spending, not necessarily real provider spending.

Retain an unresolved reservation until complete real-cost evidence justifies settling it. Account for outstanding charges even when the key endpoint is available but lagging; use real proxy costs for fault-run accounting. Add runner-level tests for incomplete accounting plus a zero delta, unavailable usage, and recovery after restart. Ledger writes also use direct truncate-and-write; use atomic replacement before claiming reservations survive a crash during persistence.

### P2 — Outcome categories still misidentify empty output and missing evidence

`src/quarry/agent.py:13` raises `RuntimeError("no change was produced")` when the agent returns an empty diff. `tools/bench_records.py:275` classifies every observed exception as `harness-exception`. A dummy `run_agent` returning an empty string reproduced this classification, so the intentional no-change path is not separately identified.

Conversely, `outcome_category('/tmp/dummy-trial', {}, '[quarry] starting')` returns `empty-output` despite lacking any completion evidence. Finalization extraction also returns all zero counts for a missing log, making unavailable telemetry indistinguishable from observed non-activation unless another field marks it missing.

Define a completion/evidence contract and test the actual Ridges-wrapped no-change exception, an unrelated runtime exception, a truncated log, a missing log, and a completed patch-producing run. Keep known no-change results distinct from infrastructure/runtime exceptions and unavailable evidence. Do not infer successful empty completion from the mere presence of a Quarry log line.
