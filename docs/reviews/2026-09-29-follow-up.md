**Quarry follow-up review — user fixes rechecked**

**Verdict:** the original normal-return P0 is fixed. All 109 current tests pass. Several edge cases remain, including three that directly affect scope, evidence or the stated last-resort policy. This is a review only; no runtime source was changed.

**The two deliberate departures**

- Repairing changes outside the named function is appropriate. The important invariant is that the final patch is in scope and subsequent validation uses the repaired code. The new named-function test exercises that correctly. The remaining scope finding below is about unnamed targets, not an objection to repair.
- Returning a guard-failing candidate when no passing candidate exists is a reasonable fallback policy: a conservative local guard can reject a correct fix. Keep hard facts such as patch applicability separate from heuristic correctness checks. The implementation still needs to enforce “only if it applies” and label failed regression checks consistently, as detailed below.

**F1 — P1: unnamed method-only scope still permits multiple method changes.**

Locations: `src/quarry/spec.py:240`, `src/quarry/spec.py:268`, `src/quarry/guard.py:234`.

Reproduction: compile `Find the query method and change only that method.`; modify both `f()` and `g()` in one Python file; provide the discovered target `(m.py, f)` to the guard.

```text
mode=discover-one-symbol
rest_frozen=false
eligible=true
changed_returns=2
```

The final `rest_frozen=True` assignment only covers symbols extracted from the statement. Discovery mode remains false, and both splicing and bounded-symbol checking exit early. Adding a target to `ScopePolicy` does not update this flag.

Required behavior: enforce symbol exclusivity in discovery mode too. Once the target is established, repair neighbouring edits and validate the repaired tree. If the target is unavailable or ambiguous, do not silently report successful scope validation.

**F2 — P1: check-generated untracked source is invisible to the evidence comparison.**

Location: `src/quarry/shell.py:137`.

The tracked-source mutation regression is fixed, but comparing only `repo.diff()` omits newly untracked files. Reproduction:

1. Edit `m.py` so `f()` imports `VALUE` from `helper.py`.
2. Run a check that creates `helper.py` with `VALUE=2`, then asserts `m.f()==2`.
3. The guard reports eligible and checks report success. The second guard is skipped because the tracked diff is unchanged.
4. Handoff removes both run-owned changes, including the helper.
5. Apply the returned patch to the restored repository and call `m.f()`.

Result: `ModuleNotFoundError: No module named 'helper'`.

This probe actually applied and executed the returned patch in a disposable repository; it was not just a mocked guard result. Bind evidence to the relevant filesystem state as well as the diff. After cleanup/normalization, confirm that the patch is self-contained and invalidate evidence that depended on removed source. Generated caches need not count as production source, but arbitrary new modules cannot be ignored.

**F3 — P1: candidates that fail regression commands are still ordinary eligible candidates.**

Locations: `src/quarry/shell.py:183`, `src/quarry/shell.py:199`.

`Candidate.eligible` receives only `report.eligible`. The `checks` result is not included. An agent run with a valid edit and a required shell check of `false` returned a patch and logged:

```text
returning candidate; evidence=1.0
```

It was not labelled last-resort. The same classification problem applies when checks time out or keep modifying the source. Returning such a patch is consistent with the user's fallback preference; representing it as a passing candidate is not.

Persist guard status, regression status and applicability separately. A candidate that fails either required guard checks or regression checks should enter the last-resort category. Preserve `None` for absent checks rather than inventing passing evidence.

**F4 — P2: a failed final apply check only produces a log message.**

Location: `src/quarry/shell.py:218`.

`handoff()` returns the diff even when `apply_check_worktree()` fails. The outer exception handler also retains the diff after cleanup/handoff errors. A targeted failure-path probe supplied a patch with nonmatching context: the actual Git check failed, but handoff returned that exact patch.

This does not mean normal valid patches still fail—the original P0 path now passes. It means the explicit “last resort only if it applies” invariant is advisory on failure paths. Reject an unappliable candidate, try another applicable stored candidate when possible, and report no usable patch if none exists. There is no useful heuristic uncertainty to preserve after Git itself rejects applicability.

**F5 — P2: comments bypass the SQL transaction-control filter.**

Location: `src/quarry/tools.py:304`.

Both queries below return an empty refusal string from `transaction_control()`:

```sql
SELECT 1; -- done
COMMIT;
```

```sql
/* end */ COMMIT;
```

The regex expects a transaction keyword immediately after whitespace, and SQL comments are never tokenized. Thus the rollback protection still accepts ordinary commented transaction-control statements. The probe exercised the parser only; it did not connect to or mutate a database. Use SQL-aware tokenization that handles comments and quoting, or constrain execution through a transaction-owning interface. Do not use a naive comment-removal regex that also changes string literals.

**F6 — P2: connection deduplication can discard resolved credentials.**

Location: `src/quarry/profile.py:163`.

An application config with a known host/name/user but `PASSWORD=get_secret()` produces an unresolved target. A complete `PG*` environment target for the same connection is then discarded because deduplication compares only engine/host/port/name/user. Sorting complete connections afterward cannot recover the discarded target.

Reproduction produced one target, still marked `unresolved: PASSWORD`, despite a valid fixture password in `PGPASSWORD`. `_postgres()` then overrides that environment variable with the target's empty password. Merge unresolved fields from complete targets or retain/rank alternatives before deduplication. Do not print credentials in diagnostics.

**Local-workspace caveat: pre-existing changes are not preserved.**

Locations: `src/quarry/guard.py:124`, `src/quarry/git.py:117`.

I staged a pre-existing edit in `notes.txt`, then ran a task scoped to `m.py`. The guard restored the notes file before handoff; both its contents and staged state were lost. Also, handoff resets the entire index before skipping `initial_dirty` paths, so that skip alone cannot preserve staging.

This is not a clean-repository competition blocker, but it contradicts the general start-state preservation claim. Either reject dirty repositories before making changes or snapshot and restore their actual contents/index state. Never rely only on path-name sets for preservation.
